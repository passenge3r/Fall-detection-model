# 跌倒检测 + 1/2/3 秒跌倒预测 FastAPI 集成说明

版本：v0.3，2026-08-15

## 一、这次新增了什么

在原有“跌倒已经发生”的检测结果之外，新增基于最近 64 帧 RTMPose 骨架序列的 1 秒、2 秒、3 秒风险预测。两个分支共用同一条摄像头视频流、同一次 RTMPose 关键点提取和同一个滑动窗口，不会为预测模块再次向萤石平台拉流。

预测结果通过原接口 `GET /v1/streams/status` 返回，不要求系统新增第二套视频接入逻辑。

## 二、压缩包结构

```text
fall_prefall_demo_system_v0.3_20260815/
├─ app/                         FastAPI、拉流、跌倒检测及预测代码
├─ models/                      ST-GCN++ 网络结构
├─ scripts/                     启动及骨架预处理必需代码
├─ weights/
│  ├─ stgcnpp/                  原跌倒检测 4 折权重
│  └─ prefall/                  新增预测 9 折权重及各折阈值
├─ .env.example                 配置模板，不含真实密钥
├─ requirements.txt
├─ requirements-api.txt
└─ start_api.ps1
```

## 三、部署

1. 解压后进入目录，创建虚拟环境。
2. 先安装与服务器 CUDA 匹配的 PyTorch，再安装 `requirements.txt` 和 `requirements-api.txt`。
3. 将 `.env.example` 复制为 `.env`，填入萤石 `AppKey`、`AppSecret`、设备序列号和服务 API Key。不要在群里传真实密钥。
4. 将 `.env` 中的值注入进程环境；也可以由师兄现有系统直接设置同名环境变量。
5. 启动：`powershell -ExecutionPolicy Bypass -File .\start_api.ps1 -HostAddress 0.0.0.0 -Port 8000`。

首次使用 RTMPose 时，`rtmlib` 会下载其人体检测和姿态 ONNX 权重并缓存到当前用户目录。若部署机不能联网，可把已有的 `%USERPROFILE%\.cache\rtmlib\hub\checkpoints` 一并复制过去。

## 四、必须配置的参数

```env
FALL_ROUTE=rtmpose_stgcnpp
FALL_CHECKPOINTS_ROOT=weights/stgcnpp
PREFALL_ENABLED=true
PREFALL_CHECKPOINTS_ROOT=weights/prefall
PREFALL_MIN_POSITIVE_FOLDS=5
```

预测权重是用 RTMPose 骨架训练的，因此开启预测时不能把 `FALL_ROUTE` 改成 YOLO-Pose 路线。

## 五、调用顺序

启动萤石摄像头处理：

```http
POST /v1/streams/start
X-API-Key: <FALL_SERVICE_API_KEY>
Content-Type: application/json

{
  "source_type": "ezviz",
  "device_serial": "<设备序列号>",
  "channel_no": 1,
  "protocol": 2,
  "quality": 2,
  "process_every_n_frames": 1
}
```

轮询结果：

```http
GET /v1/streams/status
X-API-Key: <FALL_SERVICE_API_KEY>
```

读取：`latest_result.prefall_prediction`。

```json
{
  "enabled": true,
  "risk_level": "MEDIUM",
  "prediction_active": true,
  "probabilities": {"1s": 0.41, "2s": 0.53, "3s": 0.61},
  "positive_folds": {"1s": 3, "2s": 6, "3s": 7},
  "min_positive_folds": 5,
  "ensemble_folds": 9,
  "pose_valid_ratio": 0.92,
  "experimental": true
}
```

## 六、前端显示建议

- `WARMUP`：正在积累 64 帧，显示“模型初始化中”。
- `POSE_UNAVAILABLE`：无人、遮挡或骨架质量不足，显示“当前无法可靠判断”，不能显示为正常。
- `NORMAL`：暂未发现 3 秒内跌倒风险。
- `LOW`：预测 3 秒内存在风险。
- `MEDIUM`：预测 2 秒内存在风险。
- `HIGH`：预测 1 秒内存在风险。
- `FALL_CONFIRMED`：原跌倒检测分支已确认跌倒。
- `RESPONSE_ACTIVE`：已进入事件处置阶段。

建议 LOW/MEDIUM/HIGH 先用于页面提示、事件记录和人工复核；正式外呼或紧急处置继续由“确认跌倒 + 持续倒地/人工确认”触发。

## 七、自检

- `GET /health` 返回 `ok: true`。
- 启动视频流后，`frames_decoded` 和 `frames_processed` 持续增加。
- 积累满 64 个已处理帧后，`prefall_prediction.risk_level` 应从 `WARMUP` 变化。
- `ensemble_folds` 必须为 9；否则说明预测权重未完整复制。
- 预览接口：`GET /v1/preview.mjpg`。

## 八、当前效果边界

模型在 PreVFall 9 人严格 LOSO 测试中的三时距宏平均为：Balanced Accuracy 0.8833、Macro-F1 0.6681、PR-AUC 0.8314。当前结果属于模拟数据集验证，真实家庭场景仍需继续采集误报样例并校准阈值，因此接口保留了 `experimental: true` 标记。
