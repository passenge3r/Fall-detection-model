# 简易跌倒监测系统上手说明

## 1. 压缩包怎样融入师兄的系统

压缩包不是一个只能单独运行的模型文件，而是一个可以独立启动的 FastAPI 微服务。师兄的业务系统不需要加载 PyTorch 模型，也不需要自己连接第二路摄像头，只需通过 HTTP 调用这个服务。

```text
萤石摄像头 / 视频文件
        ↓（只拉取一次）
FastAPI 视频服务
        ↓
RTMPose 人体关键点（两个分支复用）
        ├─ 原跌倒检测模型 → 已发生跌倒、确认状态
        └─ 新跌倒预测模型 → 1/2/3 秒概率、LOW/MEDIUM/HIGH
        ↓
GET /v1/streams/status
        ↓
师兄系统的护理站页面、告警记录与消息模块
```

典型集成流程：

1. 师兄部署并启动压缩包里的 FastAPI 服务。
2. 业务系统通过 `POST /v1/streams/start` 告诉服务处理哪台摄像头。
3. 服务在后台持续拉流、提取骨架并运行两个模型。
4. 业务系统每 0.5～1 秒调用 `GET /v1/streams/status`。
5. 将 `latest_result.prefall_prediction` 显示为预测卡片；将确认事件写入原告警流程。
6. 如果师兄的后端支持 WebSocket，后续可由轮询升级为服务主动推送，但初版使用 HTTP 轮询最容易联调。

## 2. 你自己运行简易系统

### Windows PowerShell

```powershell
cd fall_prefall_demo_system_v0.3_20260815
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -r requirements-api.txt
powershell -ExecutionPolicy Bypass -File .\start_api.ps1
```

如果电脑已有项目使用的虚拟环境，可直接复制或复用，不必重复下载依赖。

启动成功后打开：

```text
http://127.0.0.1:8000/
```

页面默认选择“内置成功样例”，点击“开始处理”即可看到完整流程，不需要萤石账号。

### 使用萤石摄像头

1. 将 `.env.example` 复制成 `.env`。
2. 填入 `YS7_APP_KEY`、`YS7_APP_SECRET`、`YS7_DEVICE_SERIAL`。
3. 重启服务。
4. 页面选择“萤石摄像头”，输入设备序列号并开始处理。

不要把包含真实密钥的 `.env` 发到群聊或提交到代码仓库。

## 3. 页面各区域含义

- 左侧：来源选择、启动/停止和带骨架标注的处理画面。
- 右侧：1 秒、2 秒、3 秒预测概率与风险等级。
- 跌倒检测状态：原模块判断当前是否已经疑似/确认跌倒。
- 骨架有效率：越高表示最近窗口中可用人体姿态越完整。
- `WARMUP`：尚未积累满 64 个处理帧。
- `POSE_UNAVAILABLE`：人体出画、遮挡或骨架质量不足，不能显示为安全。

## 4. 当前演示系统的定位

该页面用于你熟悉接口、给老师演示以及帮助师兄联调。正式系统可复用相同 API 和字段，但需要换成师兄现有的登录权限、数据库、消息推送和护理站 UI。
