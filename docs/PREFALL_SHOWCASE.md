# 跌倒检测与风险预警阶段成果展示

更新日期：2026-08-15

## 当前已经能做到

1. 从实时视频帧提取 RTMPose 人体骨架，并使用64帧因果窗口进行连续分析。
2. 跌倒发生前分别输出“1秒内、2秒内、3秒内跌倒”的风险概率。
3. 将概率转换为 `NORMAL / LOW / MEDIUM / HIGH` 四级风险；跌倒确认后切换至事件处置状态。
4. 通过9折模型投票降低单模型偶然误判；当前默认至少5/9折同意。
5. 无人、遮挡或关键点质量不足时返回 `POSE_UNAVAILABLE`，不把无效画面误报为风险，也不伪装成正常状态。
6. FastAPI能够输出风险等级、三个时距的概率、各折投票数、骨架有效率和告警原因，供护理站WebUI集成。

## 严格受试者独立测试结果

数据集：PreVFall；9名受试者LOSO；每折训练满300轮并加载验证集最佳检查点。

| 指标 | 结果（均值±标准差） |
|---|---:|
| Macro Balanced Accuracy | 0.8833 ± 0.0726 |
| Macro-F1 | 0.6681 ± 0.1401 |
| Macro PR-AUC | 0.8314 ± 0.1592 |

| 预警时距 | Balanced Accuracy | Recall | F1 | PR-AUC |
|---|---:|---:|---:|---:|
| 1秒 | 0.9084 | 0.8408 | 0.6661 | 0.8410 |
| 2秒 | 0.8817 | 0.7982 | 0.6887 | 0.8309 |
| 3秒 | 0.8598 | 0.8047 | 0.6494 | 0.8222 |

## 72个跌倒事件的平均预警效果

将9折留出测试预测按原视频聚合，每个跌倒视频只由未见过该受试者的对应折评估：

| 风险时距 | 成功预警事件 | 事件召回率 | 平均提前量 | 中位提前量 |
|---|---:|---:|---:|---:|
| 1秒/高风险 | 69/72 | 95.83% | 0.61秒 | 0.67秒 |
| 2秒/中风险 | 70/72 | 97.22% | 1.41秒 | 1.65秒 |
| 3秒/低风险 | 72/72 | 100.00% | 2.29秒 | 2.37秒 |

上述结果采用单窗口达到验证集阈值即算预警，适合证明模型具有提前感知能力，但误报仍高：36段非跌倒视频中，1/2/3秒分支分别有7/15/24段出现过误报。因此事件召回率不能脱离误报率单独宣传。

若要求连续两个窗口确认，72个跌倒事件中1/2/3秒分支分别成功46、61、68个，平均提前量分别为0.22、0.97、1.70秒；误报有所下降，但仍未达到无人值守部署要求。

## 成功演示样本

- 数据：PreVFall Subject 1，侧视角、眩晕后向前跌倒。
- 测试协议：使用fold 1模型；Subject 1的所有视频均未参与该模型训练或阈值选择。
- 官方跌倒起始帧：523。
- 首次中风险预警：跌倒前2.00秒。
- 首次高风险预警：跌倒前0.93秒。
- 展示内容：原视频、RTMPose骨架、三个预警概率、验证集阈值、风险等级和官方跌倒倒计时。
- 视频编码：H.264/yuv420p，1280×720，约11.1秒。

演示视频：`reports/prevfall_prefall_success_subject1.mp4`

## 当前还不能宣称

- 不能宣称已经在真实老人家庭环境达到同等指标；PreVFall属于模拟数据。
- 不能宣称一定能提前3秒预测所有跌倒；三个时距的召回率约为0.80–0.84，仍有漏报。
- 不能仅凭预警分支自动拨打急救电话；目前适合界面提示、事件记录和人工复核。
- 不能用9折模型在训练数据上的集成输出冒充无偏测试成绩；正式指标来自每位受试者只由其对应留出折评估的结果。
- 真实摄像头仍需测量每小时误报次数、事件级召回率、实际提前量和端到端延迟。

## 推荐现场展示顺序

1. 播放成功预警视频，说明模型在跌倒前2秒由正常切换为中风险、跌倒前约1秒切换为高风险。
2. 展示9折300轮学习曲线和20/300轮逐折对比图，说明结果不是单个视频的偶然案例。
3. 打开FastAPI接口状态，展示 `risk_level`、`probabilities`、`positive_folds` 和 `pose_valid_ratio`。
4. 用无人或遮挡画面展示 `POSE_UNAVAILABLE` 安全门控，说明系统不会在看不清时给出虚假“正常”。
