# OTA升级

# 1. 注册开放平台账号

使用OTA设备升级服务，您需要[注册萤石开放平台账号](https://open.ys7.com/console/application.html)。

**【注册开放平台账号流程】**

1. 登录/注册萤石账号：进入萤石开放平台控制台，进行账号[注册](https://open.ys7.com/view/register/register.html)。
2. 企业认证：进行账号信息企业认证（企业名称、企业代码、法案人代表名称）
   ![](https://resource.eziot.com/group2/M00/00/A7/CtwQF2TR_COAMCHnAABFU9lup6w354.png)
3. 创建应用：进入控制台-我的账号-应用信息页面，填写应用名称、行业、行业名称、软件名称，完成后点击提交在右侧获取appkey、secret、accesstoken信息。

# 2. 开通流程

## 2.1前提条件

请确保您的账号：

1. 已购买萤石开放平台企业版套餐服务
2. 账号下有余额（用于存储升级包）

## 2.2打开OTA设备升级服务控制台

登录账号后，打开OTA设备升级服务控制台：<https://open.ys7.com/console/ota>

# 3. 使用流程

## 3.1产品管理

- 产品：对应一个具体的产品型号，例如萤石的CS-CTQ6X设备即为一个产品。设备、模块、升级包、升级任务均属于产品下。
- 产品相关操作：

| 操作名称 | 操作含义 |
| --- | --- |
| 创建产品 | 在账号下创建产品，后期可以在产品下创建设备、创建升级任务等功能。 |
| 查看产品信息 | 支持查询账号的相关信息，包括产品ID等开发中所用的平台生成信息。 |
| 修改产品信息 | 支持修改产品的基础信息。 |

- 产品相关信息：

| 信息名称 | 信息含义 | 信息用途 |
| --- | --- | --- |
| 产品名称 | 产品的中文名称。 | 可用于您标识产品信息，例如：萤石CS-CTQ6X云台机。 |
| 所属应用AppKey | 账号下应用的应用标识，产品所属于应用之下。 | 可用于开放平台侧的故障排查等。 |
| 产品ID | 萤石开放平台中产品的唯一标识。 | 在业务中用于唯一标识产品信息。在SDK集成等中均需应用。 |
| 产品型号 | 产品的具体型号。 | 可便于您区分和管理产品，建议对应产品的实际型号，例如：CS-CTQ6X。 |
| 产品密钥 | 产品的密钥信息。 | 确认产品使用权限，在SDK集成等中均需应用。 |
| 产品所属品类 | 产品所属的品类，例如：智能安防、智能家居、会议商显、VR/AR终端、工业设备、智能车载、智能可穿戴、陪伴型机器人、智能教育、智能零售、物联网网关、其他设备。 | 标识产品类别。 |
| 芯片型号 | 硬件使用的芯片型号。 | 用于标识硬件产品所用的芯片型号。 |
| 操作系统 | 硬件所使用的操作系统，例如：Android、Linux、Windows、其他。 | 不同操作系统决定集成SDK的不同。 |
| 备注信息 | 产品的备注。 | 可用于备注产品的信息。 |

## 3.3设备管理

- 设备：设备所属于产品之下，是具体某一个升级设备。添加在产品之下。（添加与传统的绑定不同，当前仅拥有升级权限）
- 设备相关操作：

| 操作名称 | 操作含义 |
| --- | --- |
| 导入设备 | 在产品下可以提前导入设备，将设备的序列号、设备名称导入账号下，后期可以预先对设备进行部分升级任务的下发，更好适应设备出售前后对于设备的管理。 |
| 激活设备 | 集成SDK的设备，在上线联网后向平台发起请求。此时会优先判断设备是否已激活，对未激活设备校验是否提前导入。最后保障每个请求设备在产品下拥有唯一的设备ID，以及便于您确认设备使用的设备序列号与设备名称。 |

- 设备相关信息：

| 信息名称 | 信息含义 | 信息用途 |
| --- | --- | --- |
| 设备序列号 | 设备实际的序列号。由您定义。需要保证产品下唯一，不可重复。 | 后期可便于您对设备进行管理和维护，建议与产品的实际序列号对应。设备首次上报时也需携带，用于首次确认设备是否提前导入。 |
| 设备名称 | 设备的中文名称。 | 便于您使用中文名称区分或备注设备。 |
| 设备ID | 设备注册并激活后平台颁发的唯一ID。萤石开放平台中设备唯一标识。 | 后期用于业务中唯一确定一台激活设备的身份。SDK在第一次注册激活成功或向平台获取并回调给设备保存，设备拿到后必须固话保证不丢失 |
| 激活状态 | 完成首次上线后的设备状态会变更为激活状态，添加后未上线激活过的设备为未激活状态。 | 设备完成过首次上线，即为激活状态。预先导入的设备为未激活状态，完成首次激活后的设备处于激活状态 |

### **3.3.1 导入设备**

要在产品下添加设备（注意，此处的添加与设备绑定不同，仅为生产关系），可以在设备上线激活前预先导入设备基础信息，后期可查询设备上线情况等数据；也可以在设备上线激活时，自动将设备添加入对应产品下。

**【预先导入】**

可以通过输入设备序列号与设备名称进行设备预先导入。操作支持单台添加或批量添加。
![](https://resource.eziot.com/group2/M00/00/A7/CtwQFmTR_o-AKYHUAAG24QcGw8o173.png)

**【激活自动添加】**

完成OTA 硬件SDK集成的设备，在上线插电后会携带设备序列号与设备名称向平台进行注册。

如设备已提前导入，且为首次激活，则分配新的设备ID；如果设备未提前导入，且为首次激活，则分配新的设备ID后将设备添加到产品下。

![](https://resource.eziot.com/group2/M00/00/A7/CtwQF2TR_rCAZxP8AAA7Veb-sUU288.png)

### **3.3.2 激活设备**

流程详见设备SDK

激活后，可在设备列表中看到对应设备序列号的信息，以及该设备的设备ID。

## 3.4模块管理

- 模块：设备所属于产品之下，包含这个产品所需升级的所有模块，不同设备之间拥有的模块、模块的版本可能都不相同。后续的设备升级也是针对设备的模块进行单独升级的。
- 模块相关操作：

| 操作名称 | 操作含义 |
| --- | --- |
| 添加模块 | 在产品下添加模块信息，后续的升级过程将针对产品下的模块进行升级 |
| 激活设备 | 集成SDK的设备，在上线联网后向平台发起请求。此时会优先判断设备是否已激活，对未激活设备校验是否提前导入。最后保障每个请求设备在产品下拥有唯一的设备ID，以及便于您确认设备使用的设备序列号与设备名称。 |

- 模块相关信息：

| 信息名称 | 信息含义 | 信息用途 |
| --- | --- | --- |
| 模块类别 | 系统/应用 注意：一个产品仅支持创建一个系统，可支持创建多个应用。 | 区分系统与应用。 |
| 模块别名 | 模块的名称，支持自定义。 | 可便于您区分模块。 |
| 模块描述 | 对模块的描述 | 便于更好的区分模块的具体内容。 |
| 模块ID | 萤石开放平台中模块唯一标识。 | 萤石开放平台中模块唯一标识。 |

### **3.4.1 添加模块**

添加该产品下所有支持升级的模块信息。后期的升级包、升级任务均需制定对产品下的某一模块进行升级。
![](https://resource.eziot.com/group2/M00/00/A7/CtwQFmTR_42AA3ZgAAHUcmLidl8065.png)

### **3.4.2 编辑模块**

支持对模块的模块别名、模块描述进行修改。
![](https://resource.eziot.com/group2/M00/00/A7/CtwQFmTR_76ASy54AAEUnMSFi_o007.png)

## 3.5升级包管理

- 升级包：升级包是针对产品下的模块部署的，目前支持上传升级包和差分包，暂不支持在线差分。在升级任务创建时，需选择升级包后才可进行任务下发。
- 升级包相关操作：

| 操作名称 | 操作含义 |
| --- | --- |
| 添加升级包 | 在产品下添加升级包，后续可在升级包中进行升级任务操作。 |
| 下载升级包 | 从控制台下载升级包。 |
| 编辑升级包信息 | 支持编辑升级包的基础信息 |
| 删除升级包 | 支持删除升级包 |

- 升级包相关信息：

| 信息名称 | 信息含义 | 信息用途 |
| --- | --- | --- |
| 升级包类型 | 整包/差分包。 | 定义升级包类型。后期的升级任务类型与升级包类型相关。 |
| 升级包名称 | 升级包的名称，支持自定义。 | 可便于区分升级包。 |
| 所属OTA模块 | 此升级包针对的升级模块。 | 指定升级目标。 |
| 升级包版本号 | 升级后，设备将处于的版本号。 版本号格式例如V5.3.3 build 200510或V5.3.3 build 20051010 | 升级后版本标识。 |
| 待升级版本号 | 仅针对差分包。升级前的版本号（仅处于该版本下的设备支持进行此升级包的升级任务）。 版本号格式例如V5.3.3 build 200510或V5.3.3 build 20051010 | 等待升级的版本号，仅用于差分包。 |
| Md5 | MD5值（[计算工具](http://resource.eziot.com/group2/M00/00/B6/CtwQFmUk8KSAf7ACAAZIoPCS_J0159.exe)） |  |
| 升级包描述 | 对升级包的描述。 | 可以更好的升级包的具体内容，例如提升了什么功能等 |

## 3.6升级任务管理

- 升级任务：选择某个升级包，对该升级包所升级的产品模块进行升级。支持提示升级或静默升级，同时支持全量/定量升级。
- 升级任务相关操作：

| 操作名称 | 操作含义 |
| --- | --- |
| 创建升级任务 | 可以选择升级包以及升级的相关配置，下发升级任务。 |
| 复制升级任务 | 可以选择当前已创建的升级任务，复制内容再次创建新的升级任务 |
| 查看升级任务/结果 | 查看升级任务的详情信息。 |
| 编辑升级任务 | 编辑升级任务的相关信息。 |
| 暂停/重启升级任务 | 可以暂停/重启升级任务。 |
| 关闭升级任务 | 支持提前关闭升级任务。 |

- 升级任务相关信息：

| 信息名称 | 信息含义 | 信息用途 |
| --- | --- | --- |
| 任务名称 | 升级任务的名称，可用于区分升级任务。 |  |
| 任务备注 | 可以用于备注升级任务的详情，例如是否为测试任务、是否为全量任务等。 |  |
| 升级包 | 本次升级任务使用的升级包。选择的升级包决定本次升级的升级版本号、待升级版本号、升级模块。 |  |
| 升级的方式 | 升级后，设备将处于的版本号。 |  |
| 升级范围 | 仅针对差分包。升级前的版本号（仅处于该版本下的设备支持进行此升级包的升级任务）。 |  |

### **3.6.1 创建升级任务**

创建对应的升级任务，创建后，设备每次连接平台时可查询可以升级的升级任务并进行升级操作。

其中，升级方式如果选择为提示升级，则需要用户手动选择后才能进行升级；如选择静默升级，设备查询到升级任务后会自动进行升级。

针对升级范围，如选择全量升级，即使设备没有提前导入，只要任务还处在升级中状态下 ，设备激活后即可获取该任务信息。如选择定量升级，则需在已导入的设备中选择对应设备进行升级，后续新增设备则无法获取到升级任务。

### **3.6.5 暂停/重启升级任务**

支持对升级任务处于升级中的任务进行升级任务的暂停与重启。暂停后，已处于将升级中的设备将继续完成升级；未进行升级的设备将暂停；已完成升级的设备不会受到影响。

### **3.6.6 关闭升级任务**

1. 对升级任务中手动关闭：关闭后，已处于将升级中的设备将继续完成升级；未进行升级的设备将停止；已完成升级的设备不会受到影响。停止后，任务将无法恢复。
2. 自动关闭升级任务：定量升级任务中，完成定量设备的升级后，将会自动关闭升级任务。
