# 智能家居中控屏集成ERTC

在智能家居场景中，很多开发者都有自己的中控屏，这些中控屏需要对接不同厂商的设备，实现与海康系公司的门禁门锁门铃设备的视频取流、对讲、开锁等能力，本文主要针对这些场景提供实践说明：

1. 开发者有中控屏开发能力，但是不愿意上萤石云，中控屏设备为Linux客户端、Android客户端
2. 需要与海康、萤石设备，或者通过国标接入的其他三方设备进行互动，这些设备已经上萤石云，比如门锁、门禁、门口机、猫眼等
3. 需要实现功能：视频取流、对讲、开锁等

说明：
如果中控屏已经通过国标接入、连萤石设备接入SDK 连接萤石云，则直接集成open SDK即可，安卓设备请参考 Open SDK：[萤石Android open SDK接入链接](/help/36)

# 产品介绍

什么是ERTC？

萤石ERTC是依托萤石云多年的网络传输技术和音视频编解码技术，为客户提供低成本、超低延时、高可靠的音视频互动服务，适用于视频会议、互动直播、语音聊天、在线教育等场景。

详见：[ERTC产品概述](/help/230)

# 0 术语表

本节旨在介绍您在使用ERTC 服务过程中可能会涉及到一些基本概念。

| 名称 | 描述 |
| --- | --- |
| 萤石开放平台 | open.ys7.com是由萤石云提供的开放业务接入平台，平台提供了大量的开发者API供您使用。后文简称为“开放平台”，“本平台” |
| RTC应用 | ERTC通过应用的形式来管理不同的业务或项目，以实现业务或项目数据的隔离。当前每个开发者名下可创建10个RTC应用。 |
| AppID | 每个RTC应用有唯一的AppID（应用标识/应用 ID）。AppId是萤石云后台用来区分不同 ERTC 应用的唯一标识，在创建应用时自动生成。不同 AppID 之间的数据不互通。 |
| 房间 | 在每个RTC应用下，可以创建多个独立的房间。房间是一个音视频会话空间，同一房间内的用户可以互相接收实时音视频数据。只有在同一个房间里的用户才可以相互接收音视频。 |
| RoomID | 房间的唯一标志为RoomID（房间号/房间ID），用于在一个 ERTC 应用中唯一标识一个房间。由开发者生成及管理。 |
| UserID | 参会者（终端或设备）的唯一标识，该标识是由开发者自定义的用户id，长度应小于128个字符。由于终端没有设备序列号，开发者需要为终端定义一个唯一标识（即UserID）,来标识RTC房间内的不同终端。 同一个 UserID同一时间只能在一个房间内，如果有相同 UserID进入房间，前一个 UserID 将会被移出房间。 |
| 萤石云开放平台地址 | 萤石云平台地址，ERTC SDK使用平台地址（例如：open.ys7.com）作为萤石云接口的前缀。 |
| ERTC | 萤石实时音视频（ezviz real time communication，简称 ERTC，下同）是依托萤石云多年的网络传输技术和音视频编解码技术，为客户提供低成本、超低延时、高可靠的音视频互动服务，适用于视频会议、互动直播、语音聊天、在线教育等场景。 |

# 1 安全令牌

开发者云服务和开发者终端请求萤石开放平台资源都需要携带安全令牌。安全令牌是保证请求合法性和数据安全性的一种凭证。通过安全令牌，开发者也能确保其在开放平台上的操作合规、安全，并且能够对平台资源进行正常、有效的访问和使用。令牌有以下几种。

| **令牌类型** | **描述** | **token获取方法**/**获取接口** |
| --- | --- | --- |
| accessToken | 开发者token，开发者云可使用该token访问开发者所有资源。仅有开发者云（服务端可以使用，设备或App等终端不可使用。） | 通过[文档概述 · 萤石开放平台API文档](https://open.ys7.com/help/81)获取AccessToken |
| 资源访问Token | 资源访问Token由开发者云颁发给终端使用，终端可以使用此token来访问被授权的资源。(旧称“小权限Token”，RTCToken是资源访问Tokenen的一种) | 使用[文档概述 · 萤石开放平台API文档](https://open.ys7.com/help/1873)本地java sdk签名颁发 |

# 2 快速接入

## 2.1 前提条件

### 2.1.1 申请开发者账号

请在[萤石开放平台](https://open.ys7.com/cn/s/index)注册开发者账号。如您已有开发者帐号，可以跳过这一步。

### 2.1.2 创建RTC应用

在开启项目之前，您需要注册一个RTC应用。

有两种方法可以创建RTC应用，您可以任选其中一种，具体创建方法详见：[创建RTC应用](/help/1995)

如果您已有一个AppID，那么也可以跳过此步骤。

### 2.1.3 开通消息推送服务

在本项目中，开发者需要知道门铃被人按下，并准备进行对讲，因此需要订阅门铃的呼叫事件。

如果您您可以在[开放平台控制台-云信令-消息推送](https://open.ys7.com/console/messagePush.html)开通消息推送服务。

消息推送服务会将门铃的呼叫事件推送给您，一般来说，萤石协议的呼叫通过ys.calling方式可以订阅到。
如果您在如何订阅门铃呼叫遇到问题，可以询问设备方使用了哪条呼叫协议，根据不同的呼叫协议，会有不同的订阅方式。

### 2.1.4 获取accessToken

开发者云服务通过accessToken访问开放平台，在访问开放平台操作之前，开发者可以使用AppKey和AppSecret生成AccessToken，详见：[根据appKey和secret获取accessToken](https://open.ys7.com/help/81)

### 2.1.5 获取ERTC SDK

不同客户端的获取地址有所不同，下载地址：[SDK获取地址](/help/1874)

其中：设备Linux的

### 2.1.5 设备要求

为了方便调试和兼容，您需要做以下两件事

- **关闭设备上的视频加密开关**。
- **请登录设备管理页面，将视频流编码设置为H.264**（一般IPC都有主子等多路码流，请全部设置为H.264）

### 2.1.6 为终端访问开放平台提供资源访问Token

与开发者的服务访问开放平台不同，如果是终端设备要访问开放平台，必须使用专门的资源访问Token资源访问Tokenen需要由开发者服务端生成，并分发给终端。开发者服务端可以下载开放平台Java SD资源访问Tokenoken。

token获取方法及使用方法参考：[Java SDK下载及使用说明](/help/2108)

以下为开发者云生成资源访问Token的示例代码：

```
GeneralResourceTokenGenerator generator = new GeneralResourceTokenGenerator();
generator.init(APP_KEY, SECRET_KEY);

GeneralResourceTokenParam param = new GeneralResourceTokenParam();
// 创建一个业务行为参数
Action action= new Action("ERTC_INFO");
//设置房间号：strRoomId
action.setAttribute("strRoomId", "ID1699430483");
//设置终端标识：customId
action.setAttribute("customId", "7ca19da6c7164bc5ad7e0a");
param.addAction(action);
// 设置appid
param.setAppid("f758a146b2b24fc7b9705e232bce9f02");
// 设置过期时间，最长过期时间为604800秒（7天）
param.setExpire(604800);
String token = generator.generateToken(param);
```

## 2.2 智慧屏接入RTC业务

本节介绍智慧屏接入方法，如何实现与萤石/海康门铃设备的音视频通话功能等。

### 2.2.1 呼叫消息传递

对接消息通知服务后，当有访客点击门铃，门铃会通过萤石云平台将 呼叫消息转发给开发者云服务。

消息服务接入文档说明：[https://open.ys7.com/help/980](/help/980)

![](https://resource.eziot.com/group1/M00/00/E9/CtwQEmVDqoyAcUysAAFX8hCTPIo302.png)

流程说明：

①点击萤石/海康门铃，设备将上报呼叫消息到萤石云

②萤石云将消息处理并推送给开发者云服务

③开发者云服务，需要自行开发，将呼叫消息推送到设备端

④设备端可以进行接听或拒绝，接听时，需要走设备加入ERTC的流程（详见2.2.2）。拒绝时，则不发起RTC服务。

### 2.2.2 智慧屏发起会议

当开发者智慧屏收到通知消息后，若选择接听，则需要调用相关SDK及相关API接口实现通话。

具体操作为智慧屏先发起一个会议。整个会议创建流程如下图所示。

![](https://resource.eziot.com/group1/M00/00/E9/CtwQE2VDqoqAHfJSAAGXejUvlyo976.png)

具体SDK及API接口操作流程及说明如下：

① 智慧屏终端已集成了萤石ERTC SDK。

② 门铃为海康/萤石门铃，且已经接入萤石云。

#### 2.2.2.1 生成会议ID

**流程说明**

1）当智慧屏终端在选择接听后，设备端的需操作ERTC SDK完成如下两个操作：

① 智慧屏申请房间并发起会议（房间）

② 邀请设备加入会议（房间）

以上操作可并行以提升响应效率。

2. 智慧屏自己加入会议流程：

a）智慧屏向开发者云服务申请建议一个新会议（房间）

该过程为开发者自行设计API，自行实现，目的是让SDK得到一个不重复的RoomId。（保障一个RTC应用下不重复即可）

**实现要点如下**

开发者云需要自行对设备请求进行验证，防止非法设备请求。

开发者云服务自行校验该设备属于自己后，向该设备下发入会信息：

- `AppID`（即在 2.1.2中创建的应用，详见术语表）
- `RoomID`（字符串，由开发者云生成，同一AppID下RoomID相同的终端会进入同一房间。建议可以根据设备序列号加前缀生成。）
- `UserID`（智慧屏在会议中的身份标识，建议可以根据设备序列号生成。）
- `萤石云平台地址`（告知智慧屏下一步去哪里发起会议）

#### 2.2.2.2 智慧屏加入会议

开发者云服务下发相关信息后，设备调用ERTC SDK，进入到RTC房间。

### 2.2.3 邀请门铃端入会并通话

#### 2.2.3.1 开发者云发起邀请

开发者云服务下发信息的同时，需要邀请萤石/海康门铃加入会议，邀请信息通过萤石云下发给设备。对应上图3.2步骤。

https://open.ys7.com/api/v3/ertc/device/invite (详见附录2.2.4邀请设备入会接口)

下发给门铃的邀请信息包括：

- `accessToken`（参考1 安全令牌 中的接口）
- `萤石门铃设备序列号`
- `通道号`
- `AppID`（同上）
- `RoomID`（需保证与下发智慧屏设备保持一致，否则会加入失败）
- `码流类型`（可以选择1：高清-主码流2：标清-子码流）
- `入会模式`

萤石云若下发邀请指令成功，返回成功响应。

#### 2.2.3.2 门铃设备入会

门铃设备在收到邀请信令后，调用ERTC SDK功能，应根据收到的入会信息（RoomId、UserId等），主动连接RTC服务器入会；
智慧屏和萤石门铃都成功入会后，即可开始通话。
