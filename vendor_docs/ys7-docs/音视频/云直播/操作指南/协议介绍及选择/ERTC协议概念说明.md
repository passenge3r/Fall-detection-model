# ERTC协议概念说明

> ERTC协议是萤石基于Google开源的WebRTC修改而来，满足弱网环境、低延迟要求，提升用户体验。

# 协议背景说明

- 设备广泛部署于安防、智慧城市、交通等场景，实时预览需求日益增长
- 用户对 低延迟（<500ms）、高清画质、连接稳定性提出更高要求
- 实际网络环境复杂：公网波动、带宽受限、丢包、抖动
- 传统TCP协议（如RTSP/RTMP）存在延迟高、抗弱网能力差，预览经常出现卡顿、延时、断流等情况，影响用户体验

因此萤石基于WebRTC能力，推出适用于IoT设备的IoT ERTC方案，满足各个硬件及用户的需求。

## 产品定义

RTC：Real-Time Communication（实时通信），支持端到端音视频低延迟传输（通常 ≤ 500ms）

- 支持IPC/NVR/DVR作为媒体源端
- 支持PC、手机App客户端等多终端预览
- 基于 自研RTC协议栈 实现P2P或中继传输
- 内嵌 QoS引擎，动态调节传输策略，适应复杂网络

# 技术说明

## 技术栈概览：

- 传输协议：RTP/RTCP(传输ECDH+DSP加密)
- 编解码：H.264 / H.265 \*，AAC / Opus
- 信令协议： 自研信令服务（信令ECDH）
- 针对监控视频扩展：非视频私有帧SEI可靠有序传输、多目交织流设备可靠、有序传输

备注：萤石ERTC协议本身同时支持H.264 / H.265，但是由于Web端SDK依赖WebRTC的浏览器解码能力，目前Chrome浏览器需要v136版本后才支持，而其他浏览器暂不支持，因此要在Web端查看H.265的ERTC视频流只能在Chrome浏览器v136及更高版本。

## 核心能力说明

当前萤石针对硬件设备的音视频能力，开发了以下能力，提升了ERTC传输效果与效率：

- 带宽估计（BandWidth Estimate）和码率调控
- 自适应编码（Adaptive Coding）
- 可伸缩视频编码（SVC）
- 强制关键帧请求
- 前向纠错（Forward Error Correction）
- 丢包重传
- 平滑发送（Paced Sender）
- 抖动缓冲区（Jitter Buffer）
- 音视频同步（Audio & Video Synchronization）
- 丢包补偿（Packet Loss Concealment）

### 概念说明：

**带宽估计（BandWidth Estimate）码率调控：**

BWE功能主要是通过RTCP反馈来估计当前传输链路的可用带宽。基本原理就是通过周期性发送数据包，基于数据包的发送间隔和接收间隔的时延变化来计算链路带宽。然后通过计算的链路带宽对发送码率进行调控。传统的算法码率调控遵循乘性减加性增的规则，且在限宽场景下时延变化波动较大，会导致带宽估计值偏低，整体带宽利用率不高（50%左右）。

萤石主要基于丢包趋势来做带宽估计，可以快速的探测出当前链路的可用带宽，且探测周期更短，带宽利用率可达80%以上

**自适应编码（Adaptive Coding）**

自适应编码策略主要是通过带宽估计来计算出当前最佳的音视频编码码率，动态调整编码器的编码参数。视频编码参数主要有码率、帧率和分辨率三个维度，具体的调整策略需要根据应用的场景和视频的内容来进行区分，主要有流畅优先和清晰度优先两种策略。

在萤石的视频通话场景中通常采用流畅优先逻辑：为了保证视频的实时性，保持帧率不降低，优先降码率，其次降分辨率。

然而在萤石的会议场景中屏幕共享则采用清晰度优先逻辑：为了保证屏幕内容的清晰度，保持分辨率和QP值不变，优先降帧率，其次降低码率。

**可伸缩视频编码（SVC）**

SVC 是传统视频编码的延伸，可提升更大的编码弹性。SVC基本原理旨在生成具有多个分层的编码流，这些分层可以根据带宽、设备和网络情况进行选择和组合，从而满足不同场景的需求。SVC的核心在于其多层结构，它允许在网络带宽不足或设备性能受限的情况下，通过丢弃部分编码层来降低码率或分辨率，从而保证视频流的基本可用性‌。

SVC通过生成多层视频流，允许不同层次的解码器根据需求选择所需的层进行解码。主要包括以下三种类型的分层结构：空间分层（Spatial Scalability）、‌时间分层（Temporal Scalability）、‌质量分层（Quality Scalability）‌。

在萤石会议场景中为了保证屏幕共享的清晰度，采用了SVC时间分层的方式，在带宽不足的情况下丢弃低层的数据，即丢弃部分视频帧，降低了帧率，减少了视频卡顿的情况。

# 设备硬件要求

| 设备接入要求 |
| --- |
| 针对码率设置，要求不启停编码器&不强制I帧 |
| qos预览设备以上次CC码率调整的值出流，若没有则以分辨率对应的网传码 |
| 分辨率对应网传码率获取（最小码率、目标码率、实际码率） |
| 预览流程中删除无效强制I帧逻辑 本地和网传参数切换优化，保证发流之前切换到网传参数，避免两个I帧 |
| 多目交织流设备需要设置实际的对应目数 |
