## 消费者消费信息

- 接口功能

   消费者使用该接口进行消息消费。consumer第一次读取消息时因建立连接耗时可能导致获取不到消息；5分钟内消费者没有消费消息，消费者将被删除，之后需要再次创建消费者，拉取消息；一次请求返回的最大字节数默认为1Mbytes。

- 请求地址

`https://open.ys7.com/api/lapp/mq/v2/consumer/messages`

- 请求方式

`POST`

- 请求参数

| 参数位置 | 参数名 | 类型 | 描述 | 是否必选 |
| --- | --- | --- | --- | --- |
| Header | Content-Type | String | application/x-www-form-urlencoded | Y |
| Body | accessToken | String | 开放平台授权过程获取的访问令牌，获取方式参考接口 https://open.ys7.com/help/81 | Y |
| Body | consumerId | String | 消费者在组中唯一标识，5分钟内未使用将自动删除，断开和消息通道的链接。读-提交模式即读取一次消息自动提交上一次消息 | Y |
| Body | offset | Int | 偏移量 | N |

- 请求示例

```
curl --location --request POST 'https://open.ys7.com/api/lapp/mq/v2/consumer/messages' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'accessToken=at.xxxxx' \
--data-urlencode 'consumerId=fab41dc1ea1043e3ad7285c96df05517'
```

- 常见问题

1、一个租户一个消息主题？如何使用？

答：租户无需关心消息主题，只需进行消息（ISAPI上行、报警消息等）订阅控制即可。建议消息消费单线程、消息处理多线程。

2、消息消费分组如何使用？

答：目前提供group1~5五个分组，每个组消息一样，不共享消息偏移，适用场景：多个业务系统需要消费同一种消息但不共享消息偏移。

3、消息生产后是否一定上报？

答：上报取决于设备是否开启上报以及用户是否订阅，ISAPI上行开关通过下行方式控制设备是否上报、报警消息通过活动检测开关控制是否上报。

4、是否可以订阅某一种类型的报警消息？

答：目前移动侦测报警占大多数，因此所有报警消息以统一一种消息类型来做处理，不支持订阅某一种类型的报警消息。

5、如何解决消息重复的问题？

答：目前消息管道只支持At Least Once的模式，消息可靠性更高，去重操作需要业务方进行处理，如萤石报警消息可通过报警ID去重、行业设备可通过内容HASH或其他方式去重。
